# CASE-004 — Post-Authentication Privileged Session Cross-Project Case Study

## 1. Case Study Purpose

This case study documents the cross-project relationship between the CYBERNOVA SOC Operations Laboratory and the CYBERNOVA SIEM Detection Lab for CASE-004.

The case demonstrates how suspicious authentication activity can be investigated by correlating authentication, session, and post-authentication command telemetry.

The primary SOC detection is:

`DET-AUTH-003 — Suspicious Post-Authentication Privileged Session`

The corresponding SOC investigation is:

`CASE-004`

The direct SOC response playbook is:

`PB-006 — Account Compromise`

The SIEM Detection Lab provides related authentication coverage through:

`RULE-002 — Successful Login After Multiple Failures`

RULE-002 is related coverage only. It does not implement the complete session-aware correlation performed by DET-AUTH-003.

This case study therefore documents both the existing integration and the remaining detection-engineering coverage gap.

All evidence described here originates from the authorized synthetic SOC laboratory environment.

## 3. SOC Detection — DET-AUTH-003

CASE-004 was generated by the SOC-side detection:

`DET-AUTH-003`

Detection name:

`Suspicious Post-Authentication Privileged Session`

Detection version:

`1.0`

The detector requires a correlated multi-stage sequence containing:

* a successful authentication;
* at least four failed authentication attempts;
* matching source IP;
* matching user;
* a correlated session start;
* at least two command executions;
* at least one privileged-activity indicator;
* correlation within a five-minute window.

The detection therefore extends beyond authentication-failure counting.

It evaluates the relationship between authentication, session establishment, command execution, and privileged activity.

The detection outcome for CASE-004 was:

```text
Alert ID: ALERT-CASE-004-DET-AUTH-003
Detection ID: DET-AUTH-003
Severity: High
Confidence: High
Status: Open
Environment: Authorized Security Laboratory
Host: lab-linux-01
User: admin
Source IP: 198.51.100.60
```

High confidence in this context means that the required detection sequence was observed in the synthetic telemetry. It does not mean that account compromise or malicious intent was confirmed.

## 7. Authentication Phase

The first stage consisted of four failed password authentication attempts.

The failures occurred against:

`admin`

from:

`198.51.100.60`

on:

`lab-linux-01`

The successful authentication was:

`EVT-004007`

The detection requires at least four failures before the successful authentication.

The observed telemetry therefore satisfies the authentication portion of DET-AUTH-003.

A successful authentication following failed attempts increases investigative priority.

However, successful authentication alone does not establish:

* credential theft;
* unauthorized access;
* account compromise;
* malicious intent.

Those conclusions require additional evidence.

## 8. Investigation Pivot — EVT-004007

`EVT-004007` is the primary authentication pivot.

The investigation proceeds from the successful authentication into the associated session.

## 9. Session Correlation — SES-004-C

The session:

`SES-004-C`

begins after the successful authentication.

The session is associated with:

* source IP `198.51.100.60`;
* user `admin`;
* host `lab-linux-01`;
* successful authentication event `EVT-004007`.

The session then provides the context for the four observed command executions.

This correlation is a major distinction between CASE-004 and a basic failed-login detection.

The SOC investigation can therefore ask:

1. Was the session authorized?
2. Was the source expected?
3. Was the account owner responsible for the activity?
4. What commands were executed?
5. Were privileged permissions accessed?
6. Did additional activity follow?
7. Did persistence, lateral movement, or other suspicious behavior occur?

The available synthetic dataset does not establish unauthorized use of the account.

---

## 10. Post-Authentication Command Correlation

Four command executions were associated with the session.

### EVT-004009 — whoami

The `whoami` command identifies the effective user context.

On its own, this command is compatible with normal administrative troubleshooting and verification.

### EVT-004010 — id

The `id` command provides identity and group information.

It can help determine the effective identity and group memberships available to the session.

It is treated as a privileged-activity indicator in the CASE-004 detection context.

### EVT-004011 — sudo -l

The `sudo -l` command examines sudo permissions available to the current account.

This is relevant to privilege analysis because it can reveal whether the account has permission to execute commands through sudo.

The command itself is not inherently malicious.

### EVT-004012 — uname -a

The `uname -a` command provides operating-system and kernel information.

This can represent ordinary administrative system identification as well as reconnaissance activity.

The command therefore requires contextual interpretation.

## 14. MITRE ATT&CK Context

The SOC case associates the observed behavior with relevant MITRE ATT&CK techniques:

```text
T1110   — Brute Force
T1078   — Valid Accounts
T1087   — Account Discovery
T1069.001 — Permission Groups Discovery: Local
T1059.004 — Unix Shell
```

These mappings provide behavioral context for the synthetic telemetry.

They do not prove that a real adversary performed the activity.

For example:

* T1110 describes the authentication-failure pattern;
* T1078 provides context for successful authentication using an account;
* T1087 relates to account discovery;
* T1069.001 relates to local permission-group discovery;
* T1059.004 provides Unix shell context.

The mapping should therefore be interpreted as technique classification rather than attribution.

## 15. Response Assessment

PB-006 requires investigation before containment decisions.

The appropriate investigation priorities include:

1. Validate whether the authentication was authorized.
2. Validate the source IP and source ownership.
3. Validate the account owner and expected activity.
4. Review the complete SSH session history.
5. Review commands before and after the observed sequence.
6. Review endpoint process telemetry.
7. Review network telemetry.
8. Check for persistence indicators.
9. Check for additional authentication activity.
10. Check whether the same source targeted other accounts or hosts.

The laboratory evidence does not support claiming that a host was isolated, an account was disabled, credentials were rotated, or systems were remediated.

Such actions remain response recommendations unless independently evidenced as performed.

SOC coverage:

    |
    +-- session start

    +-- command execution
    |
    +-- command count
    |

Therefore:

> RULE-002 provides related authentication coverage, but there is currently no equivalent SIEM rule implementing the complete session-aware privileged post-authentication correlation of DET-AUTH-003.

This is a documented engineering gap rather than a defect that should be artificially hidden.

No new SIEM rule is introduced by this case study.

## 18. Detection Limitations

The CASE-004 SOC detector has documented limitations.

Potential false positives include:

* legitimate administrator activity;
* administrator authentication mistakes;
* repeated password retries;
* shared administrative accounts;
* automated authentication workflows;
* normal system-discovery commands;
* authorized troubleshooting.

Potential detection misses include:

* fewer than four authentication failures;
* missing session telemetry;
* missing session IDs;
* fewer than two command events;
* commands outside the correlation window;
* non-password authentication;
* incomplete endpoint telemetry;
* incomplete authentication telemetry.

These limitations reinforce the requirement for investigation rather than treating the alert as automatic proof of compromise.

## 21. Lessons Learned

CASE-004 demonstrates that authentication failures alone may not provide enough context for effective SOC investigation.

The successful authentication event becomes more significant when correlated with:

* session establishment;
* administrative identity;
* command execution;
* privilege discovery;
* system discovery.

The session ID:

`SES-004-C`

is especially valuable because it links authentication to post-authentication behavior.

The commands:

```text
whoami
id
sudo -l
uname -a
```

must be interpreted in context.

None of them is inherently malicious.

The detection becomes meaningful because of the sequence in which they occur.

The case also demonstrates the importance of distinguishing:

```text
Observed evidence
        ↓
Analyst interpretation
        ↓
Hypothesis
        ↓
Confirmed finding
```

High detection confidence should not be converted into an unsupported claim of compromise.

## 25. Final Case Study Conclusion

CASE-004 demonstrates a complete SOC investigation pattern in which authentication, session, and command telemetry are correlated into a single investigation.

The SOC-side chain is:

```text
DET-AUTH-003
      ↓
CASE-004
      ↓
PB-006
```

The related SIEM coverage is:

```text
RULE-002
      ↓
Successful-after-failures
authentication coverage
```

The SIEM rule does not currently reproduce the full DET-AUTH-003 correlation.

The available evidence confirms suspicious authentication followed by a correlated administrative session and post-authentication discovery activity.

It does not confirm account compromise, malicious intent, persistence, lateral movement, data access, or exfiltration.

The case therefore provides both operational SOC evidence and a concrete detection-engineering feedback point:

> Authentication correlation is useful, but session-aware post-authentication correlation provides substantially richer investigative context.

CASE-004 is suitable for cross-project portfolio evidence because it demonstrates detection, correlation, investigation, evidence discipline, response planning, and honest identification of remaining engineering gaps.
